# muse-mcp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Go MCP server (stdio) that lets Claude Code generate images and chat
through the owner's muse.ai account. It drives a dedicated Chrome profile and
keeps saved character and scene references.

**Architecture:** One binary. `internal/musepage` holds every muse.ai selector
and in-page script and drives one tab. `internal/browser` owns the Chrome
process: its profile, lock, hidden/visible mode and tabs. `internal/muse` is
the service: the mutex, chat bookkeeping, the approval hand-off and the
wait-for-result rules. Small leaf packages handle the reference library, prompt
building, output files and the chat registry. `internal/tools` maps all of
this onto MCP tools. A fake muse page (`internal/fakemuse`) served by
`httptest` lets every browser-level test run offline in headless Chrome.

**Tech Stack:** Go 1.26, `github.com/modelcontextprotocol/go-sdk` v1.8.0,
`github.com/chromedp/chromedp` v0.21.0, `golang.org/x/image` v0.47.0 (webp
decode), stdlib `image/png`, `image/jpeg`, `log/slog`.

**Spec:** `docs/superpowers/specs/2026-10-29-muse-mcp-design.md`. Read it
first. §3 has the verified page facts, and the spike scripts in
`docs/superpowers/specs/spike/` are working reference code for the page logic.

## Global Constraints

- Module path `pp/muse-mcp` (directory `~/go/src/pp/muse-mcp`); binary `cmd/muse-mcp`.
- State root `~/.muse-mcp/` (override `MUSE_MCP_HOME`, used by tests): `chrome-profile/`, `library/`, `chats.json`, `muse-mcp.log`, `lock`.
- Chrome binary default `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`, override `MUSE_CHROME`. macOS first.
- Production base URL `https://muse.ai`. New chat `<base>/thread/new`. Chat ID = the UUID in `<base>/thread/<uuid>`.
- Never auto-approve. Approval timeout **10 minutes** → click Deny.
- One tool call at a time (global mutex), released when a call returns `needs_approval`.
- At most **10 attachments** per request (after expanding saved references).
- Image wait **4 min**, extendable to **10 min** while busy. Chat wait **5 min**, extendable to **10 min** while busy. Text-only grace about **10 s** before the one nudge.
- Never log cookies, tokens, request or response bodies. Logs go to `~/.muse-mcp/muse-mcp.log`. stdout is MCP only.
- Only send into chats the server created (`chats.json`). Never touch the owner's chats.
- Reference names: `^[a-z0-9][a-z0-9-]*$`. Kinds: `character`, `scene`.
- Output formats by extension: `.webp` (as is), `.png`, `.jpg`/`.jpeg` (converted). Never overwrite: `name-1.ext`, `name-2.ext`, …
- Tests that need Chrome call `browser.FindChrome()` and `t.Skip` when it returns an error. No test touches the network except `MUSE_LIVE=1` tests.

## Review Focus

1. **Claude Code cancels a tool call mid-wait** (ctx cancelled): the mutex is released, no pending state leaks, and the next call works. Test in Task 9.
2. **The owner closes the hidden or visible Chrome window by hand**: the next call relaunches Chrome instead of failing forever. Test in Task 7.
3. **A reference image path doesn't exist or isn't an image, or a saved reference name is unknown**: the error names the bad path or name and comes back *before* Chrome is touched. Tests in Tasks 3 and 10.
4. **muse returns a PNG or JPEG instead of webp**: conversion sniffs the bytes and doesn't trust the MIME type. Test in Task 4.
5. **Unsupported `output_path` extension (`.gif`, none)**: rejected up front with the supported list, before any generation (no wasted quota). Tests in Tasks 4 and 10.

### Task 3: Prompt builder

**Files:**
- Create: `internal/prompt/prompt.go`
- Test: `internal/prompt/prompt_test.go`

**Interfaces:**
- Consumes: `library.Ref`, `library.Character`, `library.Scene` (Task 2).
- Produces:
  - `type Input struct { Prompt, Change string; Characters []library.Ref; Scene *library.Ref; References []string; ReferenceNotes, AspectRatio string }`
  - `type Built struct { Text string; Attachments []string }` (absolute paths, in the order the text numbers them)
  - `const MaxAttachments = 10`
  - `const Nudge = "Please attach the final image here in the chat, as a single image."`
  - `func Build(in Input) (Built, error)`

Attachment order: each character's images (in the given order), then the scene's images, then `References`. Wording is fixed here, and kept in this one file so it can be tuned later:

```
reference line (character): Image {n} is the character reference "{name}": {description}. Keep face, fur/hair, markings, outfit and proportions exactly.
  (a ref with k images: "Images {n}–{n+k-1} are the character reference ...")
reference line (scene):     Image {n} is the scene reference "{name}": {description}. Keep layout, objects, lighting and style exactly.
reference line (ad hoc):    Image {n} is a reference image.   (+ " Note: {ReferenceNotes}" once, after the last ad hoc line, if set)
with Change:   "Generate a new image. Change ONLY: {Change}. Keep everything else identical: same character(s), same scene, same lighting, same framing and camera angle, same style. Do not add or remove anything else."
               (+ "\n\n{Prompt}" if Prompt also set)
no refs, no Change: "Generate an image: {Prompt}"
refs, no Change:    "Generate an image: {Prompt}" after the reference lines
AspectRatio:   append " Aspect ratio {AspectRatio}."
always last:   "\n\nAttach the final image here in the chat as a single image."
Layout: reference lines (one per line), blank line, instruction, blank line, final line.
```

  - `type ImageWait struct { ... }`; `func NewImageWait(base musepage.State, t Timing, start time.Time) *ImageWait`; `func (w *ImageWait) Step(s musepage.State, now time.Time) Verdict`; `func (w *ImageWait) NewImages(s musepage.State) []musepage.Image`; `func (w *ImageWait) Nudged()` (call after sending the nudge; the next text-only result is `Refused`)

Rules from spec §4.7 and §4.7a:
- Approval present → `NeedsApproval`, which takes precedence over everything else.
- Image `Done`: a new image with a `blob:` src, and `!Busy` continuously for `ImageSettle`.
- Image text-only: new agent text, no new image, `!Busy` for `TextOnlyGrace`. Returns `Nudge` the first time and `Refused` after `Nudged()`.
- Image timeout: after `ImageTimeout`, `TimedOut` unless `Busy`, and always at `ImageMax`.
- Chat `Done`: new agent text, `!Busy`, and agent count plus last text unchanged for `ChatStable`. Or unchanged for `ChatForcePolls` consecutive steps even if `Busy`.
- Chat timeout: `ChatTimeout`, extended while `Busy`, hard stop at `ChatMax`.
- `Stalled` doesn't change the verdict here. The service logs it.

**Files:**

**Interfaces:**

  - `type ChatRequest struct { Message, ChatID string; Attachments []string; SaveImagesTo string }`
  - `type PendingApproval struct { ChatID, ID, Text string; ExpiresAt time.Time }`
  - `type Result struct { Status string /* "done" | "needs_approval" | "timeout" */; ChatID, ChatURL, Reply string; Images []output.Saved; Approval *PendingApproval }`

  - `func (s *Service) Chat(ctx context.Context, r ChatRequest) (Result, error)`
  - `func (s *Service) Decide(ctx context.Context, chatID, approvalID string, approve bool) (Result, error)`
  - `func (s *Service) Status(ctx context.Context) (StatusInfo, error)`
  - `func (s *Service) Close()` (stops approval timers)
  - Errors (exported, with messages that tell Claude the next step): `ErrLoggedOut` ("Log in to muse.ai in the window that just opened, then try again."), `ErrUnknownChat` ("unknown chat_id: only chats started by muse-mcp can be continued; start a new chat"), `ErrAwaitingApproval` ("this chat is waiting for an approval decision; call muse_decide_approval or wait for it to time out"), `ErrNoSuchApproval` ("no such pending approval (the server may have restarted); open the chat in muse.ai to decide it there: <url>"), `ErrApprovalTimedOut` ("already denied (timed out)"), and `RefusedError{Reply string}` ("muse replied without an image: <reply>").

Behavior (spec §4.2–§4.7a):
- Hold the mutex for the whole call. Release it (and the tab stays open) when returning `needs_approval`. On ctx cancel: return `ctx.Err()`, release the mutex, and keep no pending state. The tab is closed.
- Logged out (`musepage.ErrLoggedOut` from `Open`): `SetVisible(true)`, open a tab on `BaseURL`, start one background login watcher, and return `ErrLoggedOut`. The watcher polls `Snapshot` every 3 s. When it sees `Ready && !LoggedOut`, it calls `SetVisible(false)` and stops.
- Any Chrome relaunch (a `SetVisible` mode change, or Chrome dying) drops all open tabs and all pending approvals (stop their timers). `Decide` on them then returns `ErrNoSuchApproval` (spec §4.3a, §4.4 item 6).
- New chat: `Open(NewChatURL)`, `Attach` if any, `Send`, then poll until `ThreadID(URL)` works and `chats.Add` it. Continuing a chat: `!Known(id)` → `ErrUnknownChat`. A pending approval → `ErrAwaitingApproval`. Otherwise reuse the open tab for that ID, or `Open(ThreadURL)`.
- Image: take the base snapshot before sending, then `ImageWait`. On `Nudge`: `Send(prompt.Nudge)` and `Nudged()`. On `Done`: `Download` each new image and `output.Save` (the first to `OutputPath`, then `-1`, `-2`, … via Save's never-overwrite rule). Close the tab.
- Chat: `ChatWait`. On `Done` or `TimedOut`: download new images to `SaveImagesTo` with `SaveInDir(…, "muse-reply")` if set, and return the reply. Keep the tab open, keyed by chat ID, so follow-ups are fast. Close tabs that have been idle for more than 15 minutes on the next call.
- `NeedsApproval`: the approval ID is `"<chatID>-<n>"`, with n counting approvals in that chat. Store the pending entry (the kind, image or chat, plus the original request) so `Decide` can resume the same wait and return the same result shape. Start a `time.AfterFunc(ApprovalTimeout)` that takes the mutex, calls `musepage.Decide(false)`, and marks it timed out.
- `Decide`: an unknown chat or ID → `ErrNoSuchApproval`. Timed out → `ErrApprovalTimedOut`. Otherwise take the mutex, stop the timer, `musepage.Decide(approve)` (on `ErrNoButton`, return the error and keep the entry pending), then resume the wait.
